# 6. Заключение

## 6.1 Основные результаты

В ходе выполнения выпускной квалификационной работы был разработан и проанализирован прототип системы помощи водителю (ADAS) для городских автобусов, включающий следующие реализованные функции:

1. **LDWS (Lane Departure Warning System)** — предупреждение о выходе из полосы движения. Реализовано на основе нейросетевой модели UFLDv2 с BEV-преобразованием и расчётом смещения автомобиля от центра полосы. Временная стабилизация через медианную фильтрацию (буфер 5 кадров) снижает дребезг предупреждений.

2. **FCWS (Forward Collision Warning System)** — предупреждение о столкновении. Реализовано на основе детекции объектов YOLOv8 (ONNX Runtime), трекинга ByteTrack и оценки дистанции по формуле тонкой линзы. Три уровня предупреждений: NORMAL, PROMPT, WARNING.

3. **LKAS (Lane Keeping Assist System)** — информирование о кривизне дороги. Реализовано на основе BEV-преобразования и полиномиальной аппроксимации с классификацией на 5 типов участков.

4. **Интегрированный пайплайн** — оркестратор `ADASProcessor` объединяет все модули в единый конвейер обработки кадра с параллельным инференсом через `ThreadPoolExecutor`.

5. **Графический интерфейс** — десктопное приложение на PySide6 с таймерной обработкой видеопотока, drag-and-drop загрузкой и визуализацией предупреждений.

## 6.3 Выявленные ограничения

1. **Приближённая оценка дистанции** — формула тонкой линзы не учитывает перспективные искажения и требует калибровки под конкретную камеру.
2. **Хардкод параметров** — пороги предупреждений, фокусное расстояние, маска объектов захардкожены в коде.
3. **Отсутствие модульных тестов** — невозможно автоматически верифицировать корректность алгоритмов.
4. **Ошибка в Soft-NMS** — из-за несоответствия типов (строка vs число в Numba JIT) фактически выполняется hard NMS.
5. **Отсутствие интеграции с RK3588 NPU** — система работает только через ONNX Runtime (CPU/CUDA).
6. **Отсутствие аудио-предупреждений** — реализованы только визуальные HMI-элементы.

## 6.4 Направления дальнейшего развития

1. **Реализация модуля TLR** — добавить детекцию светофоров на основе специализированной модели (например, YOLOv8 с дообучением на наборе LISA) и классификацию состояния (красный/жёлтый/зелёный).

2. **Калибровка камеры** — реализовать автоматическую калибровку фокусного расстояния и внутренних параметров камеры (через шахматную доску или самооценку по известным размерам объектов).

3. **Улучшение оценки дистанции** — заменить формулу тонкой линзы на метод монокулярной оценки глубины (monocular depth estimation) или стерео-визуальную оценку.

4. **Интеграция с RK3588 NPU** — конвертация ONNX → RKNN, использование RKNN Toolkit для deployment на NPU.

5. **Параметризация конфигурации** — вынести все пороги, пути к моделям и параметры камеры в YAML/JSON-конфигурационный файл.

6. **Добавление юнит-тестов** — покрытие ключевых модулей (NMS, расчёт дистанции, BEV-преобразование, логика предупреждений).

7. **Аудио-предупреждения** — добавить звуковые сигналы через PyAudio или системный API.

8. **Оптимизация пайплайна** — заменить ThreadPoolExecutor на асинхронную обработку с очередями; исследовать возможность инференса в одном ONNX-сеансе для обеих моделей.

9. **Улучшение визуализации** — заменить наложение иконок через альфа-маски на более гибкий рендеринг (для.embedded-экранов).

10. **Обработка ошибок** — добавить глобальную обработку исключений в `process_frame()` с fallback-рендерингом.

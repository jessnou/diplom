# 4b. Обзор системы ADAS (Vision-Guard)

## 4b.1 Назначение системы

Vision-Guard — прототип системы помощи водителю (ADAS), анализирующей видеопоток с фронтальной камеры и выдающей предупреждения трёх типов:

- **LDWS (Lane Departure Warning System)** — контроль смещения автомобиля относительно центра полосы. Система определяет, сместился ли автомобиль влево или вправо от центра, и выдаёт предупреждение при отклонении больше допустимого порога.
- **LKAS (Lane Keeping Assist System)** — информирование о кривизне дороги. Система классифицирует участок дороги как прямой, лёгкий поворот (влево/вправо) или крутой поворот (влево/вправо).
- **FCWS (Forward Collision Warning System)** — контроль дистанции до объектов впереди и предупреждение о риске столкновения. Система детектирует автомобили, пешеходов, грузовики и мотоциклы, отслеживает их перемещение, оценивает расстояние и предупреждает при опасном сближении.

## 4b.3 Архитектура системы

Система построена по модульному принципу с чётким разделением ответственности. Центральный оркестратор (`adas_pipeline.py`) объединяет все компоненты в единый конвейер обработки.

### Модуль coreEngine.py — движок инференса

Базовый абстрактный класс `EngineBase` определяет интерфейс для движков инференса. Единственная реализация — `OnnxEngine` — обеспечивает:

- Инициализацию ONNX Runtime-сессии с автоматическим выбором провайдера (GPU при наличии CUDA, иначе CPU).
- Настройку параметров производительности: количество внутриоперационных потоков (`intra_op_num_threads = cpu_count / 2`), межоперационных потоков (`inter_op_num_threads = 1`), графовые оптимизации.
- Определение типа входных данных (`float16` или `float32`) на основе метаданных модели.
- Выполнение инференса через `session.run()`.

### Модуль ObjectDetector — детекция объектов

Отвечает за обнаружение объектов дорожной сцены на кадре. Включает:

- **YoloDetector** (`yoloDetector.py`) — детектор на базе семейства YOLO (v5–v10). Препроцессинг: масштабирование с сохранением пропорций (класс `Scaler`), конвертация BGR→RGB, нормализация на 1/255, формирование NCHW-тензора через `cv2.dnn.blobFromImage`. Постпроцессинг: транспонирование выхода для YOLOv8+, фильтрация по confidence-порогу, Soft-NMS с JIT-компиляцией через Numba для подавления дублирующихся детекций.

- **EfficientdetDetector** (`efficientdetDetector.py`) — альтернативный детектор с собственной схемой препроцессинга: нормализация ImageNet (mean/std по каналам), транспонирование в NCHW. Выходные тензоры: `_raw_boxes`, `_raw_class_ids`, `_raw_class_confs`.

- **SingleCamDistanceMeasure** (`distanceMeasure.py`) — оценка расстояния до объектов по формуле тонкой линзы: `D = (H_real × f) / H_px`, где `H_real` — эталонная высота класса (справочник из реальных размеров: человек=160 см, автомобиль=150 см, грузовик=346 см и т.д.), `f = 200` — фокусное расстояние в пикселях, `H_px` — высота bounding box. Результат конвертируется из футов в метры. Выбор ближайшего объекта в полосе — через сортировку по дистанции и `cv2.pointPolygonTest` для проверки попадания нижней точки bbox в полигон полосы.

Структура результата детекции — датакласс `RectInfo` с полями: координаты (x, y, width, height), confidence, метка класса.

### Модуль ObjectTracker — трекинг объектов

Реализует алгоритм ByteTrack для устойчивого отслеживания объектов между кадрами:

- **BYTETracker** (`byteTracker.py`) — многошаговая ассоциация:
  1. Высокоуверенные детекции (score > 0.5) сопоставляются с существующими треками через IoU-дистанцию с fuse_score (порог 0.8).
  2. Низкоуверенные детекции (0.1 < score < 0.5) сопоставляются с оставшимися треками (только IoU, порог 0.5).
  3. Неподтверждённые треки сопоставляются с оставшимися детекциями.
  4. Новые треки инициализируются для нераспределённых высокоуверенных детекций.

- **Kalman Filter** (`kalman_filter.py`) — фильтр Калмана с 8-мерным вектором состояния: координаты центра (x, y), соотношение сторон (a), высота (h) и соответствующие скорости (vx, vy, va, vh). Используется для предсказания положения трека на следующем кадре.

- **Linear Assignment** — задача оптимального назначения решается алгоритмом Йонкера-Волгенанта (`lap.lapjv`).

- Визуализация: отрисовка bounding box с полупрозрачной заливкой (`cv2.addWeighted`), траекторий движения (последовательность окружностей), направлений (медиана векторов смещения), идентификаторов треков.

### Модуль TrafficLaneDetector — детекция разметки

Отвечает за обнаружение дорожной разметки и геометрический анализ полосы:

- **UltrafastLaneDetector** (UFLD v1) — детекция на основе row-based классификации. Делит изображение на сетку (100 столбцов для TuSimple, 200 для CULane) и предсказывает положение каждой линии в каждом ряду.

- **UltrafastLaneDetectorV2** (UFLD v2) — улучшенная версия с row- и column-анкорами. Поддерживает датасеты TuSimple, CULane и CurveLanes. Выходные данные: четыре линии разметки (левая-боковая, левая-эго, правая-эго, правая-боковая). Препроцессинг: BGR→RGB, ресайз с обрезкой верхней части (crop_ratio=0.8), нормализация ImageNet. Постпроцессинг: softmax по локациям строк/столбцов, формирование словаря линий, валидация (линия считается обнаруженной, если количество точек > 2 и `exist_row` > половины ячеек).

- **PerspectiveTransformation** (`perspectiveTransformation.py`) — преобразование кадра и точек разметки в Bird's Eye View (вид сверху) через `cv2.getPerspectiveTransform` и `cv2.warpPerspective`. Адаптивные режимы коррекции исходных точек (`"Top"`, `"Bottom"`, `"Default"`) на основе положения обнаруженных линий. Метод `calcCurveAndOffset()` выполняет полиномиальную аппроксимацию второго порядка (`np.polyfit`) левой и правой эго-линий в BEV-пространстве, вычисляет радиус кривизны по формуле `R = (1 + (2Ay + B)²)^(3/2) / |2A|` и боковое смещение автомобиля относительно центра полосы (в метрах, с использованием калибровочных констант `xm_per_pix = 3.7/700` и `ym_per_pix = 30/720`).

### Модуль taskConditions.py — логика предупреждений

Класс `TaskConditions` реализует временную стабилизацию измерений и пороговую логику выдачи предупреждений:

- **Временная стабилизация** — кольцевые буферы фиксированного размера (5 для дистанции и смещения, 10 для кривизны) накапливают последние измерения. Применяется медианная фильтрация (`np.median`) и выбор моды для подавления шума и кратковременных ложных срабатываний.
- **Пороговая логика:**
  - FCWS: `distance ≤ 1.5 м` → WARNING; `1.5 < distance ≤ 3.0 м` → PROMPT; иначе NORMAL.
  - LDWS: `|offset| > 0.65 м` → LEFT/RIGHT (с подавлением на поворотах); иначе CENTER.
  - LKAS: `curvature ≤ 500` → HARD_LEFT/HARD_RIGHT; `curvature > 500` → EASY_LEFT/EASY_RIGHT/STRAIGHT.
- **Калибровка BEV** — адаптивное переключение режимов перспективной трансформации при детекции осцилляций или прямых участков дороги.

### Модуль adas_pipeline.py — центральный оркестратор

Класс `ADASProcessor` — главный управляющий компонент. Метод `initialize()` создаёт и настраивает все подсистемы (детекторы, трекер, BEV-трансформацию, панель визуализации, логику предупреждений). Метод `process_frame()` реализует полный пайплайн обработки одного кадра.

Класс `ControlPanel` отвечает за визуализацию:
- `DisplayBirdViewPanel()` — мини-окно BEV (25% от размера кадра) в правом верхнем углу.
- `DisplaySignsPanel()` — иконки поворотов/смещения и текстовые статусы FCWS/LDWS/LKAS в левом верхнем углу.
- Цветовая схема предупреждений: зелёный = норма, жёлтый = неизвестно, оранжевый = предупреждение, красный = опасность.

Датакласс `ADASMetrics` фиксирует результаты обработки каждого кадра: время инференса объектов и разметки, статусы предупреждений.

### Модуль main_desktop.py — десктопное приложение

PySide6-приложение с графическим интерфейсом:
- Загрузка видеофайла через drag-and-drop.
- Таймерная обработка кадров (`QTimer`, интервал `1000 / FPS`).
- Отображение результата через `QPixmap`.
- Статус-бар с метриками: `FCWS=... | LDWS=... | LKAS=... | obj=Xs lane=Ys`.
- Опциональная запись выходного видео с оверлеями (`*_out.mp4`).
- Фильтрация классов: детектируются только `person`, `car`, `truck`, `bus`, `motorbike`.

Параметры командной строки: выбор размера модели YOLO (`--yolo-size`), путь к пользовательской модели (`--yolo-path`), отключение параллельного инференса (`--no-parallel`), пропуск кадров для разметки (`--lane-skip`), масштабирование кадра (`--downscale`).

## 4b.4 Поток обработки одного кадра

Ниже описан полный цикл обработки одного видеокадра от захвата до формирования выходного изображения с оверлеями.

### Шаг 1: Захват и препроцессинг

Кадр в формате BGR поступает из `cv2.VideoCapture` (или из GUI-таймера). При заданном параметре `downscale < 1.0` кадр масштабируется для снижения нагрузки на инференс.

### Шаг 2: Параллельный инференс

Через `ThreadPoolExecutor(max_workers=2)` одновременно запускаются:

- `object_detector.DetectFrame(infer_frame)` — детекция объектов (YOLO/EfficientDet).
- `lane_detector.DetectFrame(infer_frame)` — детекция разметки (UFLD/UFLDv2).

Детекция разметки может запускаться не на каждом кадре (параметр `lane_skip_frames`), так как геометрия полосы меняется медленно — это даёт значительный прирост производительности.

После получения результатов детекции объектов применяется фильтрация по `allowed_labels` — оставляются только целевые классы (пешеходы, автомобили, грузовики, автобусы, мотоциклы).

### Шаг 3: Трекинг объектов

Координаты bounding boxes, confidence-оценки и метки классов передаются в `BYTETracker.update()`. Трекер сопоставляет новые детекции с существующими треками, обновляет их состояние (Kalman-фильтр) и инициализирует новые треки для ранее неотслеживаемых объектов.

### Шаг 4: Оценка дистанции и поиск ближайшего объекта

`SingleCamDistanceMeasure.updateDistance()` вычисляет расстояние до каждого обнаруженного объекта по формуле тонкой линзы. Затем `calcCollisionPoint(area_points)` сортирует объекты по дистанции и находит ближайший, чья нижняя точка попадает внутрь полигона текущей полосы (область `area_points`, сформированная детектором разметки). Для проверки попадания используется `cv2.pointPolygonTest`.

### Шаг 5: BEV-преобразование и расчёт геометрии полосы

При стабильном состоянии системы (`TaskConditions.CheckStatus()`) и валидной области полосы выполняется:

1. Динамическая коррекция параметров перспективного преобразования (`updateTransformParams`).
2. Проецирование кадра в Bird's Eye View (`transformToBirdView`).
3. Проецирование точек линий разметки в BEV (`transformToBirdViewPoints`).
4. Расчёт направления и радиуса кривизны дороги, а также бокового смещения (`calcCurveAndOffset`):

```
left_fit  = np.polyfit(left_y,  left_x,  2)  # полином второй степени
right_fit = np.polyfit(right_y, right_x, 2)

# Радиус кривизны (формула для параболы y = Ax² + Bx + C)
R_left  = ((1 + (2*A_left *y_eval + B_left)² )^(3/2)) / |2*A_left|
R_right = аналогично

curvature = (R_left + R_right) / 2      # средний радиус (метры)
offset    = (veh_pos - center_x) * xm_per_pix  # смещение (метры)
```

### Шаг 6: Логика предупреждений

Измеренные значения дистанции, смещения и кривизны передаются в `TaskConditions`:

- `UpdateCollisionStatus(distance, area_status)` — добавляет дистанцию в буфер, применяет медианную фильтрацию, определяет уровень риска столкновения (NORMAL → PROMPT → WARNING).
- `UpdateOffsetStatus(offset)` — добавляет смещение в буфер, определяет направление смещения (CENTER → LEFT/RIGHT), с подавлением ложных срабатываний на поворотах.
- `UpdateRouteStatus(direction, curvature)` — добавляет кривизну в буфер, классифицирует тип дороги (STRAIGHT → EASY_LEFT/RIGHT → HARD_LEFT/RIGHT), запускает адаптивную калибровку BEV-трансформации.

### Шаг 7: Визуализация

На копию исходного кадра последовательно накладываются:

1. Линии разметки (`lane_detector.DrawDetectedOnFrame`) с цветовой индикацией статуса смещения.
2. Полигон текущей полосы (`lane_detector.DrawAreaOnFrame`) с цветовой индикацией риска столкновения.
3. Bounding boxes детекций (`object_detector.DrawDetectedOnFrame`).
4. Треки с траекториями, направлениями и ID (`object_tracker.DrawTrackedOnFrame`).
5. Дистанции до объектов (`distance_detector.DrawDetectedOnFrame`).
6. BEV-панель в правом верхнем углу (`display_panel.DisplayBirdViewPanel`).
7. Иконки и текстовые статусы в левом верхнем углу (`display_panel.DisplaySignsPanel`).

### Шаг 8: Возврат результата

Метод `process_frame()` возвращает кортеж: кадр с наложенными оверлеями и структуру `ADASMetrics` с временами инференса и статусами предупреждений.

## 4b.5 Поддерживаемые модели

### Модели детекции объектов

Система поддерживает семейство моделей YOLO (v5, v5 Lite, v6, v7, v8, v9, v10) и альтернативно EfficientDet. Модели хранятся в формате ONNX в директории `ObjectDetector/models/`. Классы объектов определены файлом `coco_label.txt` (80 классов COCO), из которых в системе задействовано 5: person, car, truck, bus, motorbike.

### Модели детекции разметки

Поддерживаются UFLD v1 и UFLD v2 с предобученными конфигурациями для датасетов:
- **TuSimple** (800×320 px, 100 griding, 56 row anchors) — прямые участки американских автострад.
- **CULane** (1600×320 px, 200 griding, 72 row anchors) — сложные городские сценарии.
- **CurveLanes** (1600×800 px, 200 griding, 72 row anchors) — специализированный датасет криволинейных дорог.

Модели хранятся в формате ONNX в директории `TrafficLaneDetector/models/`.

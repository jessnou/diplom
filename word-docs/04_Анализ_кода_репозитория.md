## 4.2 Описание ключевых модулей

### 4.2.1 Модуль coreEngine.py — движок инференса

**Файл:** `coreEngine.py` (100 строк)

Базовый класс `EngineBase` определяет абстрактный интерфейс для движков инференса: `get_engine_input_shape()`, `get_engine_output_shape()`, `engine_inference()`.

Класс `OnnxEngine` — единственная реализация, обеспечивающая:

- Инициализацию ONNX Runtime-сессии с автоматическим выбором провайдера: при наличии CUDA → `CUDAExecutionProvider`, иначе → `CPUExecutionProvider`.
- Настройку потоков: `intra_op_num_threads` = `cpu_count // 2` по умолчанию, `inter_op_num_threads` = 1.
- Определение типа входных данных: `float16` или `float32` на основе метаданных модели.
- Вызов инференса через `session.run()`.

Ключевой метод:

```python
def engine_inference(self, input_tensor):
    output = self.session.run(
        self.__output_names, {self.__input_names[0]: input_tensor}
    )
    return output
```

**Оценка:** Модуль компактный и функциональный. Архитектура позволяет добавить TensorRT- или RKNN-движок путём наследования от `EngineBase`. Недостаток: для TensorRT/GPU требуются импорты `pycuda` и `tensorrt` на уровне модуля (отмечено в README), что может привести к `ImportError` при отсутствии этих пакетов.

Поддерживает конвертацию в форматы `xyxy` и `xywh`.

#### Класс YoloDetector (yoloDetector.py:45-185)

Наследует от `ObjectDetectBase` и `YoloLiteParameters`. Ключевые особенности:

1. **Препроцессинг** (`__prepare_input`, строки 87-93):
   - `Scaler` с сохранением пропорций (`keep_ratio=True`);
   - Конвертация BGR → RGB, нормализация на 1/255;
   - Формат NCHW через `cv2.dnn.blobFromImage()`.

2. **Постпроцессинг** (`__process_output`, строки 95-126):
   - Транспонирование выхода для YOLOv8/v9/v10;
   - Фильтрация по confidence-порогу (`box_score`);
   - Декодирование якорных рамок для YOLOv5 Lite;
   - Вычисление координат `xyxy`.

3. **NMS** — используется Soft-NMS (`NMS.fast_soft_nms`, строки 161-256 в utils.py), реализованный с JIT-компиляцией Numba (`@jit(nopython=True)`).

4. **Поддерживаемые модели:** YOLOv5, YOLOv5_Lite, YOLOv6, YOLOv7, YOLOv8, YOLOv9, YOLOv10.

#### Класс EfficientdetDetector (efficientdetDetector.py:11-105)

Альтернативный детектор. Отличия препроцессинга:
- Нормализация ImageNet: `(img / 255 - mean) / std`, где `mean = (0.406, 0.456, 0.485)`, `std = (0.225, 0.224, 0.229)`.
- Формат входа: NCHW через `np.transpose`.
- Три выходных тензора: `_raw_boxes`, `_raw_class_ids`, `_raw_class_confs`.

#### Класс Scaler (utils.py:30-99)

Утилита масштабирования изображений и координат:
- `process_image()` — ресайз с сохранением пропорций и паддингом (серый 114);
- `convert_boxes_coordinate()` — обратное масштабирование координат detecций в исходное пространство изображения;
- `convert_kpss_coordinate()` — масштабирование ключевых точек.

#### Класс SingleCamDistanceMeasure (distanceMeasure.py:6-115)

Оценка дистанции по формуле тонкой линзы:

```python
distance = (self.RefSizeDict[label][0] * self.f) / (ymax - ymin)
distance = distance / 12 * 0.3048  # конвертация футов в метры
```

Где:
- `self.f = 200` — фокусное расстояние (в пикселях);
- `RefSizeDict` — справочник эталонных высот по классам;
- `(ymax - ymin)` — высота bounding box в пикселях.

Выбор ближайшего объекта в полосе (`calcCollisionPoint()`):
- Сортировка по дистанции;
- `cv2.pointPolygonTest()` для проверки попадания нижней точки объекта в полигон полосы.

Ограничения:
- Порог `ymax <= 650` (маска отсеивает объекты в нижней части кадра, но захардкожен);
- Формула не учитывает перспективные искажения и калибровку камеры;
- Нет адаптации к фокусному расстоянию камеры.

### 4.2.3 Модуль ObjectTracker — трекинг объектов

**Файлы:** `ObjectTracker/byteTrack/byteTracker.py` (216 строк), `ObjectTracker/byteTrack/matching.py`, `ObjectTracker/byteTrack/dtypes/strack.py`, `ObjectTracker/byteTrack/dtypes/kalman_filter.py`, `ObjectTracker/core.py` (245 строк)

#### Класс BYTETracker (byteTracker.py)

Реализация алгоритма ByteTrack [3]:

1. Разделение детекций на высоко- (score > `track_thresh=0.5`) и низкоуверенные (0.1 < score < 0.5).
2. Первая ассоциация: IoU-distance + fuse_score + LAP assignment (порог 0.8).
3. Вторая ассоциация: IoU-distance без fuse_score (порог 0.5).
4. Активация новых треков (score > `det_thresh = track_thresh + 0.1 = 0.6`).
5. Удаление потерянных треков (`frame_id - end_frame > max_time_lost`).

Параметры трекера:
- `track_thresh = 0.5` — порог уверенности для трекинга;
- `track_buffer = 30` — буфер кадров для потерянных треков;
- `match_thresh = 0.8` — порог IoU для первой ассоциации;
- `min_box_area = 10` — минимальная площадьbbox для отрисовки.

#### Визуализация треков (core.py)

- `plot_bbox()` — отрисовка bbox с полупрозрачной заливкой (`cv2.addWeighted`);
- `plot_trajectories()` — траектории движения в виде последовательности окружностей;
- `plot_directions()` — стрелки направления движения (медиана векторов смещения).

### 4.2.4 Модуль TrafficLaneDetector — детекция разметки

**Файлы:** `TrafficLaneDetector/ufldDetector/ultrafastLaneDetectorV2.py` (201 строк), `TrafficLaneDetector/ufldDetector/core.py` (180 строк), `TrafficLaneDetector/ufldDetector/perspectiveTransformation.py` (233 строк), `TrafficLaneDetector/ufldDetector/utils.py` (24 строк)

#### Класс UltrafastLaneDetectorV2 (ultrafastLaneDetectorV2.py)

Наследует от `LaneDetectBase`. Ключевые особенности:

1. **Конфигурация моделей** (ModelConfig):
   - TuSimple: 800×320, griding_num=100, 56 row_anchors;
   - CULane: 1600×320, griding_num=200, 72 row_anchors;
   - CurveLanes: 1600×800, griding_num=200, 72 row_anchors.

2. **Препроцессинг** (`__prepare_input`, строки 92-107):
   - BGR → RGB;
   - Ресайз с обрезкой верхней части (crop_ratio=0.8 для TuSimple);
   - Нормализация ImageNet.

3. **Постпроцессинг** (`__process_output`, строки 109-173):
   - Поддержка 4- и 6-канального выхода (с/без confidence);
   - Softmax по row/column локациям;
   - Формирование словаря полос: `left-side`, `left-ego`, `right-ego`, `right-side`;
   - Валидация полос: полоса считается обнаруженной, если количество точек > 2 и `exist_row` > половины ячеек.

4. **Обновление области полосы** (`__update_lanes_area` в core.py:150-158):
   - Полигон формируется из `left-ego` и `right-ego` точек;
   - При `adjust_lanes=True` — полиномиальная аппроксимация (`np.polyfit(y, x, 2)`).

#### Класс PerspectiveTransformation (perspectiveTransformation.py)

BEV-преобразование и расчёт кривизны/смещения.

**Инициализация:**
- Исходные точки (`src`): 4 точки трапециевидной зоны в нижней части кадра;
- Целевые точки (`dst`): прямоугольная BEV-зона;
- Матрицы гомографии: `M = cv2.getPerspectiveTransform(src, dst)`.

**Динамическая коррекция** (`updateTransformParams()`, строки 39-86):
- Три режима: `"Top"`, `"Bottom"`, `"Default"`;
- Adaptive update исходных точек на основе обнаруженных полос.

**Расчёт смещения и кривизны** (`calcCurveAndOffset()`, строки 145-213):

```python
left_fit = np.polyfit(left_lanes[:, 1], left_lanes[:, 0], 2)
right_fit = np.polyfit(right_lanes[:, 1], right_lanes[:, 0], 2)

# Радиус кривизны (в условных единицах)
left_curverad = ((1 + (2*A*y + B)**2)**1.5) / |2*A|
curvature = (left_curverad + right_curverad) / 2

# Смещение (в метрах)
lane_xm_per_pix = 3.7 / lane_width_px
distance_from_center = (veh_pos - center_x) * lane_xm_per_pix
```

Калибровочные константы:
- `ym_per_pix = 30/720` — метров на пиксель по Y;
- `xm_per_pix = 3.7/700` — метров на пиксель по X (стандартная ширина полосы 3,7 м).

### 4.2.5 Модуль taskConditions.py — логика предупреждений

**Файл:** `taskConditions.py` (307 строк)

Класс `TaskConditions` реализует:

1. **Временную стабилизацию** через кольцевые буферы `LimitedList` (размеры: 5, 5, 10).
2. **Медианную фильтрацию** — `np.median()` и моду `max(set(...), key=count)` для агрегации.
3. **Пороговую логику:**
   - FCWS: `distance ≤ 1.5 м` → WARNING; `1.5 < distance ≤ 3.0 м` → PROMPT; иначе NORMAL.
   - LDWS: `|offset| > 0.65 м` → LEFT/RIGHT (с подавлением на поворотах); иначе CENTER.
   - LKAS: `curvature ≤ 500` → HARD_LEFT/HARD_RIGHT; `curvature > 500` → EASY_LEFT/EASY_RIGHT/STRAIGHT.

4. **Калибровку BEV** (`_calibration_curve()`, строки 99-119):
   - При `curvature ≥ 15000` на протяжении 3 кадров → переключение в `"Default"` режим.

5. **Детекцию смены полосы** (через `toggle_oscillator_status`):
   - Если все измерения в буфере смещений > 0.2 (право) или < -0.2 (лево) → `"Top"` режим BEV.

### 4.3.4 Архитектурные замечания

**Положительные аспекты:**
1. Хороше разделение ответственности: каждый модуль — отдельная директория с чётким API.
2. Использование абстрактных базовых классов (`EngineBase`, `ObjectDetectBase`, `LaneDetectBase`) обеспечивает расширяемость.
3. Паттерн Strategy: выбор модели детектора через `ObjectModelType` enum.
4. Параллельный инференс через `ThreadPoolExecutor` — однако GIL Python ограничивает реальный параллелизм CPU-вычислений; приONNX Runtime с многопоточностью выигрыш может быть ограничен.

**Ограничения и проблемы:**
1. **Хардкоженные константы:** `f=200` в distanceMeasure.py, `ymax <= 650`, `distance_thres=1.5`, `offset_thres=0.65`, `curvae_thres=500` — не вынесены в конфигурационный файл.
2. **Отсутствие юнит-тестов:** в репозитории нет ни одного тестового файла.
3. **Смешение стилей:** часть кода использует табы, часть — пробелы; докстринги есть не везде.
4. **Отсутствие типизации:** аннотации типов `typing` используются непоследовательно.
5. **Импорт pycuda/tensorrt** в coreEngine.py может вызывать ImportError при CPU-only установке.
6. **Класс LimitedList** в taskConditions.py реализует кольцевой буфер через наследование от `list` с ручным удалением элементов — лучше использовать `collections.deque(maxlen=N)`.

## 4.4 Фрагменты кода с комментариями

### Фрагмент 1: Параллельный инференс (adas_pipeline.py:346-370)

```python
if self.parallel and self._executor is not None:
    obj_future = self._executor.submit(self.object_detector.DetectFrame, infer_frame)
    lane_future = self._executor.submit(self.lane_detector.DetectFrame, infer_frame) if run_lane else None

    obj_future.result()
    object_infer_time = round(time.time() - object_time, 2)

    if self.allowed_labels is not None:
        self.object_detector._object_info = [
            obj for obj in self.object_detector.object_info if str(obj.label).lower() in self.allowed_labels
        ]

    if lane_future is not None:
        lane_future.result()
        lane_infer_time = round(time.time() - object_time, 4)
        self._cached_lane_result = None
    else:
        lane_infer_time = 0.0
```

**Комментарий:** Параллелизм реализован через `ThreadPoolExecutor`. ONNX Runtime внутри каждого `DetectFrame()`.Release GIL при инференсе, что позволяет реальный параллелизм. Однако имя переменной `object_time` используется как стартовая точка для обоих замеров, поэтому `lane_infer_time` включает время ожидания object-задачи.

### Фрагмент 2: Soft-NMS (utils.py:162-192, сокращённо)

```python
@staticmethod
@jit(nopython=True)
def __fast_soft_nms(dets, sc, iou_thr=0.3, sigma=0.5, score_thr=0.001, method='linear'):
    # ... сортировка по confidence, итеративный пересчёт IoU ...
    for i in range(N):
        # swap max score to position i
        # compute IoU with all remaining
        if method == 1:   # linear soft-NMS
            weight[ovr > iou_thr] = weight[ovr > iou_thr] - ovr[ovr > iou_thr]
        elif method == 2: # gaussian
            weight = np.exp(-(ovr * ovr) / sigma)
        else:             # hard NMS
            weight[ovr > iou_thr] = 0
        scores[pos:] = weight * scores[pos:]
    keep = dets[:, 4][scores > score_thr]
    return keep.astype(np.int32)
```

**Комментарий:** Реализация поддерживает три метода NMS (hard, linear soft, gaussian soft), но параметр `method` передаётся как строка, а в Numba JIT-функции сравнение строк не поддерживается. В текущем коде `method='linear'` будет сравниваться как `method == 1`, что всегда `False`, и фактически выполняется hard NMS. Это потенциальная ошибка.

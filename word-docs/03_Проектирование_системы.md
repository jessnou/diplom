# 3. Проектирование системы

## 3.1 Архитектура программного обеспечения

Архитектура системы построена по модульному принципу с чётким разделением ответственности. Каждый функциональный блок (детекция объектов, детекция разметки, трекинг, оценка дистанции, логика предупреждений, визуализация) выделен в отдельный модуль с определённым интерфейсом.

## 3.3 Поток данных на один кадр

1. **Захват кадра** — `cv2.VideoCapture` или PySide6-таймер читает BGR-кадр.
2. **Препроцессинг** — кадр масштабируется (опционально `downscale`).
3. **Параллельный инференс** — `ThreadPoolExecutor` запускает детекцию объектов и детекцию полос одновременно.
4. **Трекинг** — bounding boxes передаются в `BYTETracker.update()`.
5. **Оценка дистанции** — `SingleCamDistanceMeasure` вычисляет расстояние до каждого объекта; выбирается ближайший внутри полигона полосы.
6. **BEV-преобразование** — точки полос проецируются в Bird's Eye View; `calcCurveAndOffset()` вычисляет смещение и кривизну.
7. **Логика предупреждений** — `TaskConditions` агрегирует измерения (медианная фильтрация) и выдаёт статусы `CollisionType`, `OffsetType`, `CurvatureType`.
8. **Визуализация** — все детекции, треки, дистанции, зоны полос, BEV-панель, иконки предупреждений накладываются на кадр.

## 3.4 Ключевые технологические решения

| Компонент | Технология | Формат модели |
|-----------|-----------|---------------|
| Детекция объектов | YOLOv5–v10 / EfficientDet | ONNX Runtime |
| Детекция разметки | UFLD / UFLDv2 | ONNX Runtime |
| Трекинг | ByteTrack (Kalman Filter + IoU) | — |
| Инференс | ONNX Runtime (CPU/CUDA) | `.onnx` |
| Визуализация | OpenCV | — |
| GUI | PySide6 (Qt) | — |
| Язык | Python 3.12 | — |
| Параллелизм | `concurrent.futures.ThreadPoolExecutor` | — |

### Обоснование выбора технологий:

1. **ONNX Runtime** — обеспечивает переносимость моделей между платформами (CPU, CUDA, NPU через ONNX → RKNN конвертацию). Поддерживает GPU-ускорение через CUDAExecutionProvider.
2. **YOLOv8 nano** — оптимальный баланс точности и скорости для встраиваемых систем (mAP 37,3%, ~80 FPS на T4).
3. **UFLDv2** — сверхбыстрая детекция разметки (~300+ FPS), формулирует задачу как row-based классификацию.
4. **ByteTrack** — превосходит SORT/DeepSORT по полноте трекинга (MOTA, IDF1), не требует реидентификационной модели.
5. **PySide6** — кроссплатформенный GUI-фреймворк, аналог PyQt6 с LGPL-лицензией.

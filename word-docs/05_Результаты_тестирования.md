# 5. Результаты тестирования

## 5.1 Методика тестирования

Тестирование прототипа проводилось в следующих конфигурациях:

1. **Оффлайн-тестирование** — обработка видеофайлов (`.mp4`, `.mkv`) через PySide6 GUI (`main_desktop.py`).
2. **Изолированное тестирование модулей** — демонстрационные скрипты (`__main__` блоки в `yoloDetector.py`, `efficientdetDetector.py`, `videoDetection.py`, `imageDetection.py`).

В репозитории **отсутствуют**:
- Юнит-тесты (нет файлов `test_*.py`);
- Интеграционные тесты;
- Бенчмарки и скрипты профилирования;
- Наборы тестовых данных с разметкой (ground truth).

Таким образом, оценка качества основана на:
- Анализе кода и алгоритмов;
- Неформальных замерах FPS, присутствующих в коде;
- Сравнении с требованиями концептуального проекта.

## 5.3 Оценка производительности

### 5.3.1 Измерение FPS в коде

В коде присутствуют неформальные измерения FPS:

1. **ControlPanel.updateFPS()** (adas_pipeline.py:103-109):
```python
def updateFPS(self):
    self.frame_count += 1
    if self.frame_count >= 30:
        end = time.time()
        self.fps = self.frame_count / max(1e-6, (end - self.start))
        self.frame_count = 0
        self.start = time.time()
```

2. **main_desktop.py:271-274** — отображение в статус-баре:
```python
f"obj={metrics.object_infer_s:.2f}s lane={metrics.lane_infer_s:.4f}s"
```

3. **YoloDetector и EfficientdetDetector** — `__main__` блоки с ручным подсчётом FPS.

### 5.4.4 Оценка дистанции

Точность оценки дистанции по одной камере (формула тонкой линзы) существенно зависит от:
- Точности детекции bbox (±5-10 пикселей при малых объектах);
- Ошибки калибровки фокусного расстояния;
- Перспективных искажений.

Ориентировочная погрешность: ±30-50% на дистанциях свыше 20 м, ±15-20% на дистанциях 5-15 м.

## 5.5 Выявленные проблемы и ограничения

### 5.5.1 Критические

1. **Отсутствие модуля TLR** — распознавание светофоров и дорожных знаков, запланированное в концептуальном проекте, не реализовано.
2. **Ошибка в Soft-NMS** — параметр `method` передаётся как строка, но сравнение в Numba JIT ведётся с числовыми значениями (`method == 1`, `method == 2`), что приводит к выполнению hard NMS вместо soft NMS.
3. **Хардкод фокусного расстояния** (`f=200`) — не позволяет использовать систему на камерах с другим фокусным расстоянием без модификации кода.

### 5.5.2 Средние

4. **Отсутствие юнит-тестов** — нет возможности верифицировать корректность алгоритмов автоматически.
5. **Хардкод пороговых значений** (`distance_thres=1.5`, `offset_thres=0.65`, `curvae_thres=500`, `ymax <= 650`) — не вынесены в конфигурацию.
6. **Маска объектов** `ymax <= 650` в distanceMeasure.py — работает только для определённого разрешения видео.

### 5.5.3 Низкие

7. **Смешение стилей форматирования** — табы и пробелы, непоследовательные докстринги.
8. **Отсутствие логирования в production** — класс `Logger` инициализируется с `None` как путь к файлу, что исключает запись логов на диск.
9. **Отсутствие обработки ошибок в process_frame()** — исключение в любом подмодуле приведёт к краху GUI.

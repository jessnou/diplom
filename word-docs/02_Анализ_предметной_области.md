# 2. Анализ предметной области

## 2.1 Роль ADAS в обеспечении безопасности дорожного движения

Системы помощи водителю (ADAS) представляют собой класс электронных систем, предназначенных для автоматизации, адаптации и улучшения безопасности вождения. Международная классификация SAE J3016 определяет шесть уровней автоматизации (от L0 до L5). Рассматриваемая система соответствует уровню L1 (информирование водителя) и частично L2 (управление отдельными функциями).

Ключевые подсистемы ADAS, реализованные в прототипе:

- **LDWS (Lane Departure Warning System)** — предупреждение о выходе из полосы движения. Система определяет смещение автомобиля относительно центра полосы и формирует предупреждающий сигнал при превышении порогового значения (0,65 м).
- **LKAS (Lane Keeping Assist System)** — информирование о кривизне дороги. Классификация участков дороги на прямые, пологие и резкие повороты позволяет водителю заранее снизить скорость.
- **FCWS (Forward Collision Warning System)** — предупреждение о столкновении. Система оценивает дистанцию до ближайшего объекта в полосе движения и классифицирует риск столкновения по трём уровням: NORMAL, PROMPT, WARNING.

## 2.2 Обзор существующих подходов к детекции дорожной разметки

### 2.2.1 Методы на основе компьютерного зрения

Традиционные подходы к детекции дорожной разметки включают:
- Преобразование Хафа для поиска прямых линий;
- Цветовая сегментация (HSV-пространство);
- Морфологические операции и фильтрация.

Данные методы обладают значительными ограничениями: чувствительность к освещению, неспособность обрабатывать криволинейную разметку, зависимость от качества дорожного покрытия.

### 2.2.2 Глубокие нейронные сети

Современные подходы основаны на свёрточных нейронных сетях:

- **SCNN (Spatial CNN)** [6] — модель для сегментации полос, использующая последовательную передачу сообщений между строками/столбцами feature-карт.
- **UFLD (Ultra Fast Lane Detection)** [2] — метод, формулирующий детекцию полос как задача row-based классификации. Отличается исключением построчной сегментации и последовательным выбором, что обеспечивает скорость инференса ~300 FPS на Tesla V100.
- **UFLDv2 (Ultra Fast Lane Detection v2)** [7] — улучшенная версия с добавлением segmentation-ветки и уверенности (exist_row/exist_col), повышающая стабильность при частичных окклюзиях.

В прототипе реализована поддержка обоих вариантов (UFLD и UFLDv2) через наследование от абстрактного класса `LaneDetectBase`, при этом основная конфигурация использует UFLDv2 с моделью, обученной на наборе данных TuSimple.

## 2.3 Обзор подходов к детекции объектов

### 2.3.1 Семейство YOLO

Семейство детекторов YOLO (You Only Look Once) является одним из наиболее производительных подходов к детекции объектов в реальном времени. В прототипе реализована поддержка YOLOv5, v6, v7, v8, v9, v10 через класс `YoloDetector`.

YOLOv8 [4] — одностадийный детектор с anchor-free архитектурой, обеспечивающий mAP 37,3% (COCO val, модель nano) при скорости ~80 FPS (T4 GPU). Модель отличается:
- Отсутствием якорных рамок (anchor-free);
- Возможностью использования NMS и Soft-NMS (реализовано в `NMS.fast_soft_nms`);
- Унифицированным форматом вывода (объектный конфиденс объединён с классовым).

### 2.3.2 EfficientDet

EfficientDet [8] — семейство моделей на основе архитектуры BiFPN и компаунд-масштабирования. В прототипе поддерживается как альтернатива YOLO через класс `EfficientdetDetector`, однако основная конфигурация использует YOLOv8.

## 2.4 Трекинг объектов: ByteTrack

ByteTrack [3] — алгоритм многообъектного трекинга, основанный на двухстадийной ассоциации:
1. **Первая ассоциация** — высокоуверенные детекции (score > `track_thresh`) сопоставляются с активными треками по IoU с учётом fuse_score.
2. **Вторая ассоциация** — низкоуверенные детекции (0,1 < score < `track_thresh`) сопоставляются с оставшимися треками по IoU без fuse_score.

Реализация в репозитории (`ObjectTracker/byteTrack/`) включает:
- Фильтр Калмана для предсказания позиции (`KalmanFilter`);
- Линейное назначение по методу LAP (`matching.linear_assignment`);
- Управление состояниями треков (Tracked, Lost, Removed).

## 2.5 Оценка дистанции по одной камере

Метод оценки дистанции основан на модели тонкой линзы:

$$D = \frac{H_{\text{real}} \cdot f}{H_{\text{px}}}$$

где $H_{\text{real}}$ — эталонная высота объекта (из справочника `RefSizeDict`), $f$ — фокусное расстояние камеры (константа 200), $H_{\text{px}}$ — высота bounding box в пикселях.

Данный метод является приближённым и не учитывает:
- Перспективные искажения по вертикали;
- Изменение масштаба объектов на разных расстояниях;
- Погрешности детекции bbox.

Справочные размеры объектов (в сантиметрах, переведённых в дюймы):

| Класс   | Высота (дюймы) | Ширина (дюймы) |
|---------|---------------|----------------|
| person  | 62,4          | 19,5           |
| bicycle | 38,2          | 25,4           |
| motorbike | 39,0       | 39,0           |
| car     | 58,5          | 70,2           |
| bus     | 124,4         | 97,5           |
| truck   | 135,0         | 97,5           |

## 2.6 BEV-преобразование и вычисление кривизны

Для вычисления смещения автомобиля от центра полосы и радиуса кривизны дороги применяется перспективное преобразование (Bird's Eye View — BEV). Исходная перспектива задаётся четырьмя точками (источник) и четырьмя точками (приёмник), затем с помощью `cv2.getPerspectiveTransform` строится матрица гомографии.

Расчёт смещения и кривизны:

1. Точки полос проецируются в BEV через `transformToBirdViewPoints()`.
2. По левой и правой полосам строится полиномиальная аппроксимация `np.polyfit(y, x, 2)`.
3. Радиус кривизны: $R = \frac{(1 + (2Ay + B)^2)^{3/2}}{|2A|}$.
4. Смещение: $d = (x_{\text{veh}} - x_{\text{center}}) \cdot x_{\text{m/pix}}$, где $x_{\text{m/pix}} = \frac{3,7}{\text{lane\_width\_px}}$.

## 2.7 Логика предупреждений и временная стабилизация

Модуль `TaskConditions` реализует агрегацию результатов детекции во времени через кольцевые буферы (класс `LimitedList`):

| Буфер                        | Размер | Метрика    |
|------------------------------|--------|------------|
| `vehicle_collision_record`   | 5      | Медиана дистанции |
| `vehicle_offset_record`      | 5      | Медиана смещения |
| `vehicle_curvature_record`  | 10     | Мода направления + медиана кривизны |

Использование медианы (а не среднего) обеспечивает устойчивость к выбросам при шумной детекции.

## 2.8 Что реализовано, а что осталось за рамками

### Реализовано в коде:

| Функция    | Статус | Примечание                          |
|-----------|--------|--------------------------------------|
| LDWS      | ✅ Полностью | UFLD/UFLDv2 + BEV + смещение      |
| FCWS      | ✅ Полностью | YOLOv8 + ByteTrack + дистанция    |
| LKAS      | ✅ Полностью | UFLDv2 + BEV + кривизна            |
| TLR       | ❌ Не реализовано | Распознавание светофоров и дорожных знаков отсутствует |

### Не реализовано:

- Модуль распознавания светофоров и дорожных знаков (TLR), предусмотренный в концептуальном проекте.
- Интеграция с аппаратным ускорителем RK3588 NPU (RKNN). В репозитории используется только ONNX Runtime (CPU/CUDA).
- Аудио-предупреждения (реализованы только визуальные HMI-элементы).
- Модуль записи логов событий и CAN-шины.

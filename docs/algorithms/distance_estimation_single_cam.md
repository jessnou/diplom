# Алгоритм: single‑camera distance estimation по bbox (монокулярная эвристика)

Документ описывает, как в проекте оценивается расстояние до объекта **по размеру bbox** и как эта оценка используется в FCWS.

---

## 1. Назначение алгоритма

**Задача.** Оценить приблизительное расстояние до объекта впереди по одному кадру (без стерео/лидара) и выделить ближайший объект в зоне своей полосы.

**Почему выбран.**

- Не требует дополнительного сенсора.
- Работает “из коробки” с любым детектором объектов.
- Достаточно для прототипа FCWS (PROMPT/WARNING) при правильной калибровке.

**Альтернативы.**

- Stereo depth / triangulation.
- LiDAR/radar‑fusion (промышленный стандарт для FCWS).
- Монокулярная глубина (DPT/MiDaS) + 3D‑геометрия.
- TTC из оптического потока / размерного расширения (time‑based метрики вместо абсолютной дистанции).

---

## 2. Теоретическая основа

### 2.1. Модель тонкой линзы (упрощённо)

При фиксированной камере и известной реальной высоте объекта $H$ его высота на изображении $h$ обратно пропорциональна расстоянию $Z$:

$$
h \approx \frac{f \cdot H}{Z}
\quad \Rightarrow \quad
Z \approx \frac{f \cdot H}{h}
$$

Где:
- $Z$ — расстояние до объекта вдоль оси камеры,
- $f$ — фокусное расстояние в “пиксельных” единицах,
- $H$ — реальная высота объекта (м),
- $h$ — высота bbox в пикселях.

### 2.2. Что именно берётся из bbox

В проекте высота объекта:

$$
h = y_{max} - y_{min}
$$

Точка для проверки принадлежности полосе:

$$
p = \left(\frac{x_{min}+x_{max}}{2}, y_{max}\right)
$$

Это приближение “контактной точки” с дорогой.

### 2.3. Предположения и источники систематической ошибки

- Камера калибрована, $f$ соответствует реальности.
- Объект стоит на плоскости дороги и видим без сильных окклюзий.
- Реальная высота класса близка к таблице (один “типовой” грузовик/легковой/человек).

Если $H$ или $f$ неверны → ошибка в $Z$ будет систематической.

- bbox,
- класс.

## 4. Pipeline обработки данных

### Входные данные

- список детекций `boxes: List[RectInfo]` из детектора объектов,
- полигон полосы `poly` (см. `collision_zone.md`).

### Предобработка

- фильтрация по классу: только объекты из `object_list`,
- фильтрация по положению: `ymax <= 650` (эмпирическое ограничение).

### Основной алгоритм

Для каждой детекции:

1) взять высоту bbox $h$,
2) взять реальную высоту класса $H$ из таблицы,
3) посчитать дистанцию:

$$
Z = \frac{H \cdot f}{h}
$$

В реализации используется таблица размеров в дюймах и затем выполняется перевод в метры (см. ниже).

### Постобработка

- сохранить список точек `distance_points = [[x_center, y_bottom, Z_m], ...]`,
- выбрать ближайший объект, попавший в полигон полосы (point‑in‑polygon).

### Интеграция с другими модулями

- `TaskConditions.UpdateCollisionStatus(vehicle_distance, lane_area, distance_thres)` преобразует расстояние в дискретный FCWS‑статус.

## 5. Реализация в проекте

- Файл: `ObjectDetector/distanceMeasure.py`
- Класс: `SingleCamDistanceMeasure`

### Таблица размеров и единицы

В коде:

- `INCH = 0.39` (см → дюйм),
- `RefSizeDict[label][0]` хранит “реальную высоту” класса в **дюймах**,
- далее:

```text
distance = (H_inch * f) / h_px
distance = distance / 12 * 0.3048
```

То есть:
- `/12` переводит дюймы → футы,
- `*0.3048` переводит футы → метры.

Инженерная интерпретация: фактически используется формула $Z \propto 1/h$, а единицы — “условно‑метрические” после конвертации.

### updateDistance(boxes)

Вход:
- `boxes: List[RectInfo]`.

Выход:
- заполняется `self.distance_points`.

### calcCollisionPoint(poly)

Вход:
- `poly: np.ndarray` — полигон своей полосы.

Выход:
- либо `[x, y, d_m]`, либо `None`.

Ключевая логика:

- сортировка по `d` (берём ближайший),
- проверка `cv2.pointPolygonTest(poly, (x,y), False) >= 0`.

## 6. Псевдокод алгоритма

```pseudo
update_distance(detections):
  distance_points = []
  for det in detections:
     if det.label not in object_list: continue
     (x1,y1,x2,y2) = det.xyxy
     if y2 > ymax_limit: continue
     h = y2 - y1
     if h <= 0: continue

     H = ref_height(det.label)      # table
     Z = (H * f) / h                # inverse proportional
     Z_m = unit_convert(Z)

     x = (x1 + x2)/2
     y = y2
     distance_points.append([x,y,Z_m])

select_target(poly):
  for p in sort_by_distance(distance_points):
     if point_in_polygon(poly, (p.x, p.y)):
         return p
  return None
```

## 7. Параметры и конфигурация

| Параметр | Где | Значение (по коду) | Влияние |
|---|---|---:|---|
| `f` | `SingleCamDistanceMeasure.f` | 200 | масштаб расстояния |
| `RefSizeDict` | `distanceMeasure.py` | class→(H,W) | систематическая ошибка по классам |
| `object_list` | `__init__` | person/bicycle/car/... | какие классы учитываются |
| `ymax <= 650` | `updateDistance` | 650 px | отсечение зон кадра |

### Инженерные рекомендации по калибровке

1) Собрать данные $(h_{px}, Z_{real})$ для нескольких расстояний на вашей камере.
2) Подобрать `f` (и/или поправочный коэффициент $k$):

$$
Z \approx k \cdot \frac{H}{h}
$$

3) Разнести `H_real` по подклассам (легковая/внедорожник/фура), если нужны более точные оценки.

### Метрики качества (прикладные)

- MAE/RMSE по $Z$ (м),
- стабильность $Z$ на фиксированной дистанции,
- FCWS‑метрики: precision/recall WARNING/PROMPT по событиям.
